# 115 STRM

把 **115 网盘**的目录结构镜像成本地 `.strm` 文件树，
交给 Emby / Jellyfin / Kodi / Infuse / 网易爆米花 等**支持 `.strm` 的**媒体服务器扫描播放。

**内网外网同一个地址、播放不占 NAS 带宽、生成的 strm 顺着 Alist 直接 302 到 115 CDN。**

> ## ⚠️ 跑之前先看这两条
>
> ### ① 你的播放器认 `.strm` 吗？（本站实测踩过的坑）
>
> **VidHub 不认 `.strm`。** 实测：同一个目录，**网易爆米花能直接播、VidHub 加载失败**。
> 排查时先怀疑过 UA 绑定 —— 那确实是另一回事（115 CDN 会把请求用的 `User-Agent` 签进直链，
> 换 UA 取链就播不了），但**根因是 VidHub 本身不支持 `.strm` 这种「内容是一个地址」的文件**。
>
> ⇒ 用 VidHub 就**直接挂 115 的原始目录**，别挂本工具生成的 strm 目录。
> 想用 strm 这套（省带宽、内网外网同址），换 Emby / Jellyfin / Kodi / Infuse / 爆米花。
>
> ---
>
> ### ② strm 内容前缀：**首次启动是空的**，去网页上填（存 `data/config.json`）
>
> 它**不是**环境变量了 —— 首次启动为空，在网页「设置 › 播放地址」里填，保存后落在
> `DATA_DIR/config.json`（跟着 data 目录走，备份 / 迁移只搬 data）。
> ⛔ 在 `.env` / compose 里写 `STRM_PREFIX=` **不生效**（网页会弹一条「还留着、已忽略」的告警
> 提醒你删掉）。**没填就跑不了** —— 工具会在动手前拦下来，而不是生成一堆播不了的 strm。
>
> 填的时候，**这是本项目最容易配错的一项**。Alist 是**按挂载路径**路由的。
> 假设 115 在 Alist 里挂在 `/媒体/影音`：
>
> | | 值 | 结果 |
> |:---|:---|:---|
> | ✅ 对 | `https://your.domain:5244/d/媒体/影音` | 302 → 115 CDN，能播 |
> | ❌ 少一层 | `https://your.domain:5244/d` | Alist 回 `storage not found` —— **状态码还是 200**，看着不像错 |
> | ❌ 用 /dav | `https://your.domain:5244/dav/xxx` | **401**（WebDAV 端点要认证）⇒ 播不了 |
>
> 填完用 `python -m app doctor --check` 或网页上的**自检**按钮验证 —— 它会真发一次请求告诉你配对没配对。

## 功能

### 同步
- **只处理你指定的目录** —— 网页上勾选（如只要 `电影` + `电视剧`，不要短剧），
  勾一个 = 处理它整棵子树；**留空 = 全部都要**
- **账号管理** —— 网页上**扫码登录**（不用手抓 cookie）或粘贴 cookie；可多账号、校验、切换、改名、删除。
  账号文件格式与同仓库的 [115offline](https://github.com/xinxinenjoy/Docker/tree/main/115offline) **完全一样**，
  挂同一份即可在任一边登录、另一边直接用
- **结构镜像** —— 115 上的目录层级原样落到本地；**只建「真正有片子」的目录**：
  没有任何视频文件的目录（空目录、只放字幕 / nfo / 图片的目录）**一条都不建**，
  不会给你留下一堆点进去空空如也的壳。以前版本建过的那种空壳会被**顺手清掉**（只删空目录，绝不碰有文件的）
- **目录树按最深层级导** —— 工具自己导目录树时**固定按最大层级（25 层）**，不再吃 115 服务端那个
  没写进文档的默认值。层级不够时导出的树会**缺子树**，表现为「很多子目录压根没出现」——
  工具看到这种「疑似截断」的条目会**当场告警**（见下文 💡）
- **只增不误删** —— 只写 `.strm`，绝不碰你其它的文件
- **删除要二次确认** —— 发现文件消失时先挂起，等 N 分钟后再扫一遍确认，确认了才删；
  一轮里消失比例超过阈值（默认 30%）直接判定异常、**一条都不删**（cookie 失效的典型症状就是「网盘看起来全没了」）
- **内容没变就不重写** —— 保住 mtime，避免媒体库每次全量重扫
- **只给视频生成 strm** —— 字幕 / nfo / 海报**不生成**（媒体服务器读它们靠「与视频同目录同名的真实文件」，
  它不认 `xxx.srt.strm`，生成了只是垃圾条目）。要这些得走「下载到本地」，那是另一件事
- **本地改过名的不动** —— 你把 `a.mkv.strm` 改名成 `我改的名字.mkv.strm`，
  工具会用**内容**认出它对应哪个网盘文件 ⇒ 不重生成、不删除（见下）
- **网盘改名照常跟** —— 115 上改了目录/文件名 ⇒ 生成新的 strm，旧的走「挂起 → 二次确认」删除

### 数据来源：只有一条路 —— 工具自己导目录树

⭐ **你什么都不用导出。** 每一轮都是同一个动作：工具调 115 的**导出目录树**任务拿到全盘结构，
解析后跟本地现状全量对账，**只写差异**。

2026-10-08 起**不再有「模式」这个概念** —— 原来那四条路（`auto` / `events` / `tree` / `api`）
里，`auto` 已经覆盖了全部场景，还留着选择器只是让人多做一个没意义的决定。已删除的是：

| 已删 | 原用途 | 为什么删 |
|:---|:---|:---|
| `events` 生活事件流 | 1 次请求拿全盘增删改 | 日常靠定时跑就够；它还要账号开「最近记录」，多一个失效点 |
| `tree` 本地固定快照 | 拿你手动放的 txt 离线算 | 「固定快照」本身就是要维护的负担，而导出只要十几秒 |
| `api` 逐层实时列目录 | 兜底 | 请求数 ≈ 目录数（实测本库 1183 个目录 ⇒ 数千请求、几十分钟），最费且最慢 |

省下选择器不是省功能 —— 留下的这条路**成本是「任务级」的，跟库多大无关**：
一个导出任务的请求量固定（提交 → 轮询 → 下载 → 删除，十来个请求），
几千个目录、几万个文件，也还是十来个请求。

> 📊 **实测**（2026-10-08，本库 727 目录 / 6071 文件 / 818 KB 导出件）：
> 提交任务 `23:07:30` → 拿到件 `23:07:43`，**13 秒**。
> 本地对账那部分更快：825 个 strm 全读一遍内容只要 **0.022 秒**（0.18 MB）。
> 所以「全量对账」这个名字听着重，实际开销可以忽略。

> 💡 「导出目录树」是 115 的**异步任务**：**不可并发、不可中止**，空目录不会被导出。
> 正常一轮十几秒；若它卡住，只能等 115 自己超时，或去网页版手动取消。
>
> 💡 **关于「没有扩展名的条目」**（2026-10-08 修正了上一版的判断）：
> 115 的导出件里，一个条目**没有扩展名**，绝不是说它是个空目录 —— 实测本盘 386 个这类条目
> **全部**是 `电影/XX（系列）/片名（年份）` 形态，即**子树被截断了**：
> 导出时按的层级不够深，深层的文件名没被写出来，只剩个目录名。
> ⇒ 所以本工具的规矩是两条：① 这类条目**不建任何东西**（不猜、不留空壳）；
> ② **看到就告警**，提示你「树可能没导全」。
> ⚠️ 而「导出层级」工具**自己钉死在最大层级 25**，正常不会再出现这种截断。
> 如果你临时想手动导一份来对照，导的时候记得**把层级拉满** —— 层级选少了，
> 表现就是「很多子目录没生成」，而不是只有一两个少。

### ⭐ 「strm 内容变了才重写」这条判据，与数据来源无关

你会关心「去掉事件流之后，还认不认得出我改过的 strm」。**认得出，而且这条判据本来就只依赖目录树。**

判定就两行 —— 逐个读本地已存在的 strm **内容**，跟「按当前设置算出来的地址」比对：

```python
if self.read_existing(key) != f.url:
    res.to_update.append(f)
```

它比的是**文件内容**，不是 mtime，也不是 115 的变更标记 ⇒ 结构上跟「数据从哪来」零耦合。
你实际会看到的三件事：

- **改了前缀设置** ⇒ 所有 strm 内容都不再匹配 ⇒ 全部重写（本来就该如此）
- **手动改了某个 strm 的地址** ⇒ 内容对不上 ⇒ 下一轮被改回来
- **手动删了某个 strm** ⇒ 树里还有、盘上没了 ⇒ 下一轮补回来


### UI
- 概览 / 同步 / 设置 / 记录 四个页签，手机和桌面两套布局
- **目录选择器** —— 从目录树里点着选（带每个目录的规模），改完**当场试算**会写多少、会删多少
  （读的是 `data/tree/` 里最新那份——就是工具自己导出的，所以跑过一轮后就能用）
- **前缀自检** —— 真发一次请求告诉你 strm 内容配对没配对（Alist 配错时会回 200 但内容是报错，肉眼看不出来）
- **预览差异** —— 先看清「会加多少、会删多少、strm 里长什么样」，再决定要不要真跑
- **只演练**开关：出厂默认开着，一个文件都不会动
- **定时** —— 「设置 › 定时扫描」填一句 5 段 cron（分 时 日 月 周，如 `0 6 * * *` = 每天 06:00），
  输入框下面**当场显示「下次运行」是什么时候**（填完不用保存也能先看一眼）；留空 = 不自动跑。
  ⚠️ 只认 `*` / 数字 / `*/N` 三种写法，**不支持列表（`1,2`）与区间（`1-5`）** —— 要那些得改代码上 `croniter`。
  ⚠️ 它是**天级**节奏：每一轮都会往 115 提交一次「导出目录树」任务，别设成分钟级。
- **首次配置清单** —— 顶部一张卡把「还差哪几步」列清楚（带 ①②③④ 序号），填完自动消失；
  没配齐时「同步」页也会**直接拦住**，不让你白跑一轮
- **设置页分两层** —— 第一屏只有真正要你决定的：**115 账号 → 播放地址 → 同步范围**
  （三张卡带 ①②③ 序号，**按这个顺序配**），加一张「参数」卡（只演练 / 定时 / 账号）；
  节流、删除判定这类**进阶参数折叠在下面**，一眼扫不到，但不动它们也完全能跑
- **脏了才出现的保存条** —— 改了没保存会一直挂在底部提醒
- 实时日志、进度、可随时停止（最长 0.25 秒响应）
- 参数在网页上改，立即生效、不用重启容器；**落点是 `data/config.json`**（跟着 data 目录走）

## 快速开始

### 方式一：`docker run`

```bash
docker run -d --name 115strm \
  -p 8767:8767 \
  -e ACCESS_TOKEN='自己定一个口令' \
  -v /path/to/data:/data \
  -v /path/to/strm:/out \
  --restart unless-stopped \
  xinxinenjoy/115strm:latest
```

> ⛔ **不要**在这里给 `STRM_PREFIX` —— 它不是环境变量了（见「起容器之后必做的一步」）。

### 方式二：`docker compose`

```yaml
services:
  115strm:
    image: xinxinenjoy/115strm:latest
    container_name: 115strm
    restart: unless-stopped
    ports:
      - "8767:8767"
    environment:
      - TZ=Asia/Shanghai
      - ACCESS_TOKEN=自己定一个口令
      - ACCOUNTS_FILE=/data/accounts.json
    volumes:
      - ./data:/data          # 参数 / 账号 / 目录树 / 回执
      - ./strm:/out           # ★ 生成的 strm 树
```

```bash
docker compose up -d
```

### 方式三：自己构建

```bash
git clone <本仓库>
cd Docker/115strm
docker build -t 115strm:latest .
```

### 起容器之后：在网页上按序号配这三样

打开 `http://部署机器的IP:8767` —— 设置页顶部有「**还差 N 步就能跑**」清单，跟着序号走即可：

1. **115 账号** —— 「设置 › 115 账号」→ 扫码登录（推荐）或粘 cookie。
2. **播放地址** —— 「设置 › 播放地址」→ strm 内容前缀：

   ```
   https://<你的 alist 域名>:5244/d/<115 在 alist 里的挂载路径>
   例：https://your.domain:5244/d/媒体/影音
   ```

   填完点旁边的**「自检」** —— 它会真发一次请求告诉你配对没配对。
3. **同步范围** —— 「设置 › 同步范围」填同步根 + 勾子目录
   （还没跑过时会提示先去「同步」页跑一轮拿目录树）。

**这三样没配齐，工具不会动手** —— 点「同步」页会被直接拦下并告诉你缺什么，
而不是生成一堆播不了的 strm。配好的东西都落在 `data/config.json` 里。

## 环境变量

**只有「引导项」走环境变量**；业务参数（**strm 内容前缀** / 节流 / 删除判定 / 扩展名…）
在网页**设置**页里管，存在 `data/config.json`，改完立即生效、不用重启容器。

| 变量 | 默认 | 说明 |
|:---|:---|:---|
| `ACCESS_TOKEN` | 空 | 网页口令。留空 = 不校验（仅限内网）；映射到公网必须设 |
| `PORT` | `8767` | 网页监听端口（容器内） |
| `DATA_DIR` | `/data` | 数据目录：`config.json` / `accounts.json` / `tree/` / `reports/` |
| `OUTPUT_DIR` | `/out` | ★ 生成的 strm 树落点 |
| `ACCOUNTS_FILE` | `DATA_DIR/accounts.json` | 账号文件位置 |
| `ACCOUNT_ID` | 空 | 用哪个账号（id）；留空 = 第一个能用的 |
| `P115_COOKIE` | 空 | 直接贴 cookie。临时 / 调试用 |

### ⛔ 这两类**别**写进环境变量

| 变量 | 为什么 |
|:---|:---|
| `STRM_PREFIX` | **已改成网页专属** —— 代码**完全不读**它。写了不生效，还会让网页弹一条「还留着、已忽略」的告警。**首次为空**，去「设置 › 播放地址」填，落在 `data/config.json` |
| `REMOTE_ROOT` · `INCLUDE_DIRS` · `SCHEDULE_CRON` | 它们**仍认**环境变量，但**环境变量优先级高于 `config.json`** ⇒ 在这儿填了，网页上再怎么改都不生效。**不用手填** —— 在网页「设置」里选 / 填就行（同步范围那边有归一化 + 配对告警 + 试算，定时那边会当场算出下次运行时刻） |

> 💡 从旧版升级上来时，`.env` / compose 里遗留的 `STRM_PREFIX` 会在**首次启动**被搬进
> `config.json`（一次性）—— 宁可多写一个键，也不让你的前缀**静默变空**。
> 之后再留着 `.env` 里那行，网页就会一直提醒你去删。

**cookie 怎么来**：优先读 `accounts.json`（同仓库的
[115offline](https://github.com/xinxinenjoy/Docker/tree/main/115offline) 扫码登录后写的就是它）
⇒ **两个容器挂同一个账号文件就能共用登录态，cookie 只维护一份**。

## 使用方法

### 0. 想先在本机看看？（不装 Docker）

```bash
cd 115strm
pip install -r requirements.txt
DATA_DIR=./data OUTPUT_DIR=./out python -m app serve
```

然后浏览器开 `http://127.0.0.1:8767/`。数据都落在 `DATA_DIR` / `OUTPUT_DIR` 里：

- `config.json` —— ★ 所有业务参数（含 **strm 内容前缀**）
- `tree/` —— 目录树会存这儿（每轮导出的叫 `tree-<时间戳>.txt`，**统一只留最近 5 份**）
- `out/` —— 生成的 strm 落这里（试跑产物，可随时清）

> 📌 仓库里另有两个**作者本机自用、不入库**的试跑脚本（`tools/run-local.sh` 与
> `启动（双击）.cmd`）—— 它们写死了本机路径，已被 `.gitignore` 排除，
> 你 clone 下来是**没有**的；用上面那三行就够了。

### 1~5. 正式用法

1. **配 115 账号** —— 「设置 › 115 账号」扫码登录（或粘 cookie）。
   **不用你去 115 网页版导目录树** —— 工具每一轮都自己导
2. **填播放地址** —— 「设置 › 播放地址」→ **strm 内容前缀**（首次是空的，必填）：
   `https://<你的 alist 域名>:5244/d/<115 在 alist 里的挂载路径>`。
   填完点旁边的**「自检 strm 前缀」** —— 它会真发一次请求告诉你配对没配对。
   **这一项不填，后面所有按钮都会被拦下来**
3. **在网页上选范围** —— 「设置 › 同步范围」：
   - **同步根目录**：你的影音库在盘上的那一层名字（例：`影音`）
   - **只处理这些子目录**：点开勾选（如 `电影` + `电视剧`），**留空 = 全部都要**
   - 保存后**当场试算**：会写多少、会删多少、strm 内容长什么样 —— 一个文件都不动
   - ⚠️ 选择器读的是 `data/tree/` 里最新那份树。第一次还没有树（工具没跑过），
     可以先什么都不勾（= 全部）跑一轮，之后再回来细选
4. **跑第一轮** —— 「同步」页 → 点「预览差异」确认
   → 保持「只演练」开着点「立即执行」看日志 → 关掉「只演练」再跑，这时才真写文件
5. **挂给播放器** —— 把 `OUTPUT_DIR` 挂给媒体服务器（Emby / Jellyfin 直接扫，
   或让 Alist 挂出去给走 WebDAV 的客户端扫）

> ⚠️ **播放器要能认 `.strm`**。Emby / Jellyfin / Kodi / Infuse / 网易爆米花都行；
> **VidHub 不支持 `.strm` 作为媒体源**（本站实测：同一个目录，爆米花能播、VidHub 不能）。
> 用 VidHub 就直接挂 **115 的原始目录**，别挂 strm 目录。

### 同步根 ↔ strm 前缀 必须配对

这是**最容易配错、又最难查**的一项。Alist 按**挂载路径**路由，而同步根是**树内路径**，
两者必须指向 115 上同一个目录 —— 共同点是「**最后一层名字**」：

| | 值 |
|:---|:---|
| 115 盘上 | `影音` ← 同步根填 `影音` |
| Alist 挂载 | `/媒体/影音` ← 前缀写 `…/d/媒体/影音` |

→ **同步根**在「设置 › 同步范围」里选；**前缀**在「设置 › 播放地址」里填（首次为空、必填）。

配错时 Alist 回 `storage not found`，而**HTTP 状态码是 200** —— 看着不像错。
所以网页上有**「自检 strm 前缀」**按钮（真发一次请求），你改了配置它当场告诉你配没配对。

### 本地 vs 网盘：谁是「真相源」

工具是**「网盘为准」的单向镜像**，但**本地改过名的 strm 会被认出来**：

| 你动了什么 | 结果 |
|---|---|
| **本地**把 `a.mkv.strm` 改名成 `我改的名字.mkv.strm` | ✅ **不动它**（用内容认出来了）—— 不重生成、不删除 |
| **本地**手动新增一个指向网盘文件的 strm | ✅ 保留（同样靠内容认出来） |
| **本地**手动改了 strm 的内容（URL 写错） | ⚠️ 会被改回正确内容（否则播不了） |
| **网盘**上把 `a.mkv` 改名成 `b.mkv` | ✅ 生成 `b.mkv.strm`；旧的挂起 → 等 N 分钟二次确认 → 删 |
| **网盘**上删了文件 | ✅ 本地对应 strm 挂起 → 二次确认 → 删 |

> 💡 靠的是**内容当「词典」**：strm 的内容天然唯一指向一个网盘文件，所以
> 「内容对得上 = 同一个文件」，不需要额外维护一本账本文件
> （账本会漂移 —— 你直接改文件系统、账本丢了/坏了都会让它和现实对不上，而账本一错就是误删；
> 内容当键是**自校验**的）。
>
> ⚠️ 代价：**同一个网盘文件**你有两份同名内容的 strm 时，只会认领一份，另一份仍判多余。

## 安全

- **出厂只演练** —— 一个文件都不写、不删，只在预览里说它本来要做什么
- **绝不碰非 strm 文件** —— 删除有双重保险（必须 `.strm`、必须解析后在输出目录内）
- **删除要二次确认** —— 挂起 → 等 N 分钟 → 再扫一遍确认 → 才删
- **异常闸门** —— 消失比例超阈值一律不删（防止 cookie 失效时把整库清空）
- **慢** —— 单请求 1–3 秒随机间隔、每 200 个请求长休 60 秒，可限定只在凌晨跑
- **原子写** —— strm 先写 `.tmp` 再 rename，媒体库读不到半个文件

### ⚠️ 说清楚：它对 115 **几乎**是只读的，但有一个例外

**你的网盘文件（视频、目录、你自己的 strm）它一个字节都不改。**
唯一的例外是为了拿到全盘结构而必须做的那两下：

| 调用 | 性质 | 后果 |
|:---|:---|:---|
| `POST /files/export_dir` | 提交「导出目录树」任务 | 在**你的 115 盘上生成一份导出件**（临时文件） |
| `POST /rb/delete` | 删掉上面那份导出件 | 走的是 **115 回收站**（`rb` = recycle bin），**非永久删除**；想留着可以用 `--keep` |

**除此之外全是只读接口**（列目录 / 查目录 id / 查状态 / 取下载链）。

> 📌 2026-10-08 删掉事件流路线后，**唯一一个会碰你网盘设置的**写接口
> （「把 115 的『最近记录』开关打开」）也随之删了 ⇒ 现在写操作就上面表格里那两处，
> 且都只作用于工具自己造的那份临时件。你的**网盘内容一个字节都不改**。

## 已知限制

- 走的是 115 **网页版接口**（非官方开放平台），存在风控可能。
  ⚠️ **每一轮都会提交一次「导出目录树」任务** ⇒ 别设成几分钟跑一次。
  它的成本是**任务级**的（十来个请求，与库大小无关，实测一轮 13 秒），
  但 115 那边一个账号同时只允许一个导出任务，所以它天生不适合高频。
  日常**按需跑**或**一天一两次**就够 —— 目录树变化本来就不频繁。
- 目录树导出件（不管是工具的自动导出、还是网页版手动导出）**都不含文件 id** ⇒
  走目录树这一路生成的 strm 只有路径、没有 id，
  删除判定只能靠「路径是否还在」——不影响正确性，只是少一层交叉验证。
- 「导出目录树」任务**不可并发、不可中止**，且**空目录不会被导出**。
  导出件里「没有扩展名的条目」**不是空目录，而是被截断的子树**（层级没导够）⇒
  本工具**不给它建任何东西**，只在回执里报个数提醒你（见上文 💡）。
- **不生成空目录** —— 没有视频文件的目录一条都不建；上一版建过的空壳会被顺手清掉
  （只删**空**目录，且绝不碰输出目录本身）。
- 导目录树时层级上限是 **25 层**（115 接口的上限）。真超过 25 层的超深目录树，
  超出部分仍然导不出来 —— 那是 115 的限制，不是本工具的。
- 115 的删除是**异步**的、列表**带缓存** ⇒ 「列表里还在」不等于「没删掉」。
  本工具的二次确认机制正是为此设计。
- 你 Alist 上的 `/dav/` 端点要认证，**不能**写进 strm —— 本工具统一用 `/d/`。
