# 115 STRM

把 **115 网盘**的目录结构镜像成本地 `.strm` 文件树，给 Emby / Jellyfin / Kodi / Infuse / 网易爆米花
等**支持 `.strm` 的**播放器扫描播放 ——
**内网外网同一个地址、播放直连 115 CDN、不占 NAS 带宽。**

带一个网页界面：预览差异、勾范围、改参数、看回执，都不用碰命令行。

> ⚠️ **播放器必须支持 `.strm`**。**VidHub 不支持**（实测：同一目录爆米花能播、VidHub 不行）⇒
> 用 VidHub 请直接挂 115 的原始目录，别挂本工具生成的 strm 目录。

## 功能

- **自己跟上网盘**：工具自己调 115 的「导出目录树」任务拿到全盘结构再做对账。
  **你不用去 115 网页版手动导 txt**。这是**任务级成本**：十来个请求，跟库多大无关（实测一轮 13 秒）
- **只处理你指定的目录**：网页上勾选（如只要 `115电影` + `115电视剧`），留空 = 全部都要
- **账号管理**：网页上**扫码登录**（不用手抓 cookie）或粘贴 cookie；可多账号、校验、切换、改名、删除
- **结构镜像**：115 的目录层级原样落地，**只建真正有片子的目录** ——
  没有任何视频文件的目录一条都不建，不会留一堆点进去空空如也的壳
- **删除二次确认**：发现文件消失先挂起 → 等 N 分钟 → 再扫一遍确认 → 才删；
  一轮消失比例超阈值直接**一条都不删**（cookie 失效的典型症状就是「网盘看起来全没了」）
- **只有一条路，没有「模式」要选**：每轮都是「自己导目录树 → 解析 → 全量对账 → 只写差异」。
  不让你维护本地快照、也不靠事件流（那两条路要么多一个失效点，要么要你手工维护一份账本）。
- **内容没变就不重写**：保住 mtime，媒体库不会每次全量重扫
- **前缀自检 + 同步根配对告警**：真发一次请求告诉你 strm 内容配对没配对（Alist 配错时会回 200 但内容是报错，肉眼看不出来）
- **只演练出厂**：一个文件都不写，先在预览里看清它要做什么

## 使用方法

**① 起容器**

```bash
docker run -d --name 115strm \
  -p 8767:8767 \
  -e ACCESS_TOKEN='自己定一个口令' \
  -v /path/to/data:/data \
  -v /path/to/strm:/out \
  --restart unless-stopped \
  xinxinenjoy/115strm:latest
```

等价的 compose：

```yaml
services:
  115strm:
    image: xinxinenjoy/115strm:latest
    container_name: 115strm
    restart: unless-stopped
    ports:
      - "8767:8767"
    environment:
      - ACCESS_TOKEN=自己定一个口令
    volumes:
      - ./data:/data     # 参数 / 账号 / 目录树 / 回执
      - ./strm:/out      # ★ 生成的 strm 树
```

> ⛔ **不要**用环境变量传 `STRM_PREFIX`（strm 内容前缀）—— 它不是环境变量了，
> 写了不生效。**首次是空的**，去网页「设置 › 播放地址」里填，保存在 `data/config.json`。

然后浏览器进 `http://<你的主机>:8767`。

**② 填播放地址** —— 网页「设置 › 播放地址」→ **strm 内容前缀**（首次为空、**必填**）：
`https://<你的 alist 域名>:5244/d/<115 在 alist 里的挂载路径>`。
旁边有**「自检」**按钮，会真发一次请求告诉你配对没配对。**不填的话工具不会动手**。

**③ 登录 115** —— 网页「设置 › 115 账号」→ **扫码登录**（推荐）或粘贴 cookie。

**④ 在网页上走一遍**

1. 「设置 › 同步范围」：填同步根（如 `115影音`），勾要处理的子目录（如 `115电影`+`115电视剧`），
   保存后**当场试算**会写多少、会删多少 —— 一个文件都不动
   （选择器读 `data/tree/` 里最新那份树；第一次还没跑过就先留空 = 全部）
2. 「同步」页 → 点「预览差异」
3. 保持「只演练」开着 → 点「立即执行」→ 看日志确认它要做的事就是你想做的
4. 关掉「只演练」→ 再执行，这时才真的写文件

> **不用你去 115 网页版导目录树** —— 工具每轮都自己导（**按最大层级 25 层**，避免子树被截断），
> 导出的那份也存在 `data/tree/`。
> ⚠️ 想**临时手动**导一份来对照也行：丢进 `/data/tree/` 即可（工具会选最新的那份）。
> 自己导的时候**层级要拉满**，层级选少了会「很多子目录压根没出现」。

> `REMOTE_ROOT` / `INCLUDE_DIRS` 也可以不写 —— 网页上点着选、自动保存。
> ⚠️ 反过来，**这两个如果写进环境变量，会盖住网页上的修改**（环境变量优先级更高）。

## 🔗 想跟同仓库的 `115offline` 共用登录态

两个容器的账号文件格式**完全一样**，挂同一份即可（在任一个里登录，另一个直接能用）：

```yaml
    environment:
      - ACCOUNTS_FILE=/shared/accounts.json
    volumes:
      - /path/to/115offline/data:/shared    # ⚠️ 挂**目录**、不要 :ro
```

> ⚠️ **必须挂目录、不能只挂单个文件**：本工具的写入是原子的（tmp + rename），
> 而单文件 bind-mount 会把挂载点钉在宿主机那个 inode 上 ⇒ `rename` 报
> `Device or resource busy`，账号根本存不进去。

## ⚠️ 最容易配错的一项：strm 内容前缀

**它在网页「设置 › 播放地址」里填（首次为空、必填），不是环境变量。**
**Alist 是按挂载路径路由的，前缀必须写到挂载点的完整路径；且它末段要等于同步根的末段。**

假设 115 在 Alist 里挂在 `/影音/115影音`、同步根填 `115影音`：

| | 值 | 结果 |
|:---|:---|:---|
| ✅ | `https://your.domain:5244/d/影音/115影音` | 302 → 115 CDN，能播 |
| ❌ | `https://your.domain:5244/d` | Alist 回 `storage not found`，**状态码还是 200**，极难察觉 |
| ❌ | `https://your.domain:5244/dav/xxx` | **401**（WebDAV 端点要认证）⇒ 播不了 |

改完在网页上点**自检 strm 前缀**，或跑 `python -m app doctor --check` —— 会真发一次请求告诉你配对没配对。

## 命令

网页是默认动作（`serve`）；命令行每条都在，适合定时 / 无人值守。

| 命令 | 说明 |
|:---|:---|
| `python -m app serve` | 开网页界面（容器默认动作），默认 `0.0.0.0:8767` |
| `python -m app sync` | **⭐ 跑一轮**（自己导目录树 + 全量对账 + 只写差异） |
| `python -m app export` | 只导一次目录树存到 `data/tree/`（`--keep` 保留 115 上那份临时件） |
| `python -m app preview` | 只预览差异，什么都不写 |
| `python -m app doctor --check` | 环境自检 + 前缀连通性验证 |
| `python -m app pending` | 看挂起待确认的删除 |
| `python -m app apply --yes` | 确认删除挂起的那些 |

> 在容器里跑：`docker exec 115strm python -m app sync`。

> ⚠️ 老命令 `auto` / `events` / `tree` / `api` 仍接受（**废弃别名**），会打一行警告后按 `sync` 跑。

## 安全

- **出厂只演练**：一个文件都不写、不删
- **绝不碰非 strm 文件**：删除有双重保险（必须 `.strm`、必须解析后在输出目录内）
- **删除要二次确认** + 异常比例闸门
- **原子写**：先写 `.tmp` 再 rename，媒体库读不到半个文件
- **慢**：单请求 1–3 秒随机间隔、每 200 个请求长休 60 秒，可限定只在凌晨跑

⚠️ **说清楚：你的网盘内容它一个字节都不改**，但为了拿全盘结构必须做两下**写操作**：
`POST /files/export_dir`（在**你的 115 盘上生成一份临时导出件**）
和 `POST /rb/delete`（删掉那份导出件 —— 走 **115 回收站**，**非永久删除**，`--keep` 可留）。
除此之外全是只读接口。视频、目录、你自己的文件，工具都不碰。

## 变量

**只有「引导项」走环境变量**；业务参数（**strm 内容前缀** / 节流 / 删除判定 / 扩展名…）
在网页**设置**页里管，存在 `data/config.json`，改完立即生效、不用重启容器。

| 变量 | 默认 | 说明 |
|:---|:---|:---|
| `ACCESS_TOKEN` | 空 | 网页口令。留空 = 不校验（仅限内网 / 本机）；映射到公网必须设 |
| `PORT` | `8767` | 网页监听端口（容器内） |
| `DATA_DIR` | `/data` | 数据目录 |
| `OUTPUT_DIR` | `/out` | ★ 生成的 strm 树落点 |
| `ACCOUNTS_FILE` | `DATA_DIR/accounts.json` | 账号文件位置 |
| `ACCOUNT_ID` | 空 | 用哪个账号（**账号 id**，不是名字）；留空 = 第一个能用的 |
| `P115_COOKIE` | 空 | 直接贴 cookie，优先级最高。临时 / 调试用 |

> ⛔ **`STRM_PREFIX` 不在上表里** —— 它是**网页专属参数**，代码**完全不读**这个环境变量：
> 首次为空，去网页「设置 › 播放地址」填，保存在 `data/config.json`。
> 写在 `.env` / compose 里不生效，只会让网页弹一条「还留着、已忽略」的告警。
> ⚠️ `REMOTE_ROOT` / `INCLUDE_DIRS` 仍可用环境变量，但**环境变量优先级更高**
> ⇒ 写了就会盖住网页上的修改，所以一般**别写**，在网页上选就行。

**cookie 怎么来**：优先读 `/data/accounts.json`（同仓库的
[115offline](https://github.com/xinxinenjoy/Docker/tree/main/115offline) 扫码登录后写的就是它）
⇒ **两个容器挂同一个账号文件就能共用登录态，cookie 只维护一份**。
