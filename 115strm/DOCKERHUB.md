# 115 STRM

把 **115 网盘**的目录结构镜像成本地 `.strm` 文件树，给 Emby / Jellyfin / Kodi / Infuse 等
**支持 `.strm`** 的播放器扫描播放 —— **内网外网同一个地址、播放直连 115 CDN、不占 NAS 带宽。**

带网页界面：勾范围、预览差异、改参数、看回执，都不用碰命令行。

> ⚠️ **播放器必须支持 `.strm`**。**VidHub 不支持** ⇒ 用 VidHub 请直接挂 115 的原始目录。

## 使用方法

**① 起容器**

```bash
docker run -d --name 115strm \
  -p 8767:8767 \
  -e ACCESS_TOKEN='换成一个够长的口令' \
  -v /path/to/data:/data \
  -v /path/to/strm:/out \
  --restart unless-stopped \
  xinxinenjoy/115strm:latest
```

等价的 compose：

```yaml
services:
  115strm:
    image: xinxinenjoy/115strm:latest
    container_name: 115strm
    restart: unless-stopped
    ports:
      - "8767:8767"
    environment:
      - ACCESS_TOKEN=换成一个够长的口令
    volumes:
      - ./data:/data     # 参数 / 账号 / 目录树 / 回执
      - ./strm:/out      # ★ 生成的 strm 树
```

打开 `http://<你的主机>:8767` —— 设置页顶部有「**还差 N 步就能跑**」清单，跟着序号走即可。

**② 登录 115** —— 「设置 › 115 账号」→ **扫码登录**（推荐）或粘贴 cookie。

**③ 填播放地址** —— 「设置 › 播放地址」填 **strm 内容前缀**（**出厂为空、必填**），点旁边**「自检」**确认真能播。**空着它不会动手。**

**④ 配范围 + 先演练一遍** —— 「设置 › 同步范围」填同步根、勾子目录（**没跑过时会提示先去「同步」页跑一轮拿目录树**）→ 「同步」页点「预览差异」→ 开着「只演练」点「立即执行」看日志，确认无误再关掉「只演练」执行。

## 功能

- **自己跟上网盘**：工具自己调 115 的「导出目录树」拿全盘结构再对账，**不用手导 txt**
- **只处理你指定的目录**：网页上勾选，**留空 = 全部**
- **账号管理**：扫码登录 / 贴 cookie，可多账号、校验、切换、改名、删除
- **结构镜像**：目录层级原样落地，**只建真有片子的目录**，不留空壳
- **删除二次确认**：发现文件消失先挂起 → 等 N 分钟 → 再扫一遍确认 → 才删；一轮消失比例超阈值则一条都不删
- **内容没变不重写**：保住 mtime，媒体库不会每次全量重扫
- **定时扫描**：填 5 段 cron（`0 6 * * *` = 每天 06:00），下面**当场显示「下次运行」**；留空 = 不自动跑。
  只认 `*` / 数字 / `*/N`，**天级**节奏、别设分钟级（每轮都要提交一次导出任务）

## 注意要点

- 🔴 **strm 内容前缀在网页「设置 › 播放地址」里填，不是环境变量** —— 写进 `.env` / compose **不生效**。
- 🔴 **前缀要写到 Alist 挂载点的完整路径**（Alist 按挂载路径路由），且末段与「同步根」一致；
  少写一层 Alist 会回 `storage not found`，**而状态码仍是 200**，肉眼看不出来 ⇒ 务必点「自检」。
- 🔴 **`/data` 要挂到宿主机**（参数 · 账号 · 目录树 · 回执）；**`/out` 也要映射出去**给播放器扫。
- 🔴 **`ACCESS_TOKEN` 一旦映射到公网务必设长**，并建议走 HTTPS（反向代理 + 证书）。
- ⚠️ **`REMOTE_ROOT` / `INCLUDE_DIRS` 写进环境变量会盖住网页上的修改**（环境变量优先级更高）⇒ 一般在网页上选就好。
- ⚠️ **想跟同仓库的 `115offline` 共用登录态**：设 `ACCOUNTS_FILE=/shared/accounts.json`，并把那个目录挂成 `/shared`。
  ⛔ **必须挂目录、不能只挂单个文件**（写入是原子的 tmp+rename；单文件 bind-mount 会把挂载点钉在宿主机 inode 上 ⇒ `rename` 报 `Device or resource busy`）
- ⚠️ **安全边界**：出厂只演练；删除有双重保险（必须 `.strm`、必须落在输出目录内）+ 二次确认，**绝不碰非 strm 文件**。
  为了拿全盘结构会做两下**写操作**：`POST /files/export_dir`（在**你的 115 盘上生成一份临时导出件**）与
  `POST /rb/delete`（删掉它，走 **115 回收站**、**非永久删除**，`--keep` 可留）。除此之外全是只读接口。

## 环境变量

业务参数（strm 内容前缀 / 节流 / 删除判定 / 扩展名…）在网页**设置**页里管，存 `data/config.json`、改完立即生效；
**只有下面这些引导项走环境变量**。

| 变量 | 默认 | 说明 |
|:---|:---|:---|
| `ACCESS_TOKEN` | 空 | 网页口令。留空 = 不校验（仅限内网 / 本机）；映射到公网必须设 |
| `PORT` | `8767` | 网页监听端口（容器内） |
| `DATA_DIR` | `/data` | 数据目录 |
| `OUTPUT_DIR` | `/out` | ★ 生成的 strm 树落点 |
| `ACCOUNTS_FILE` | `DATA_DIR/accounts.json` | 账号文件位置 |
| `ACCOUNT_ID` | 空 | 用哪个账号（**账号 id**，不是名字）；留空 = 第一个能用的 |
| `P115_COOKIE` | 空 | 直接贴 cookie，优先级最高。临时 / 调试用 |
| `REMOTE_ROOT` / `INCLUDE_DIRS` / `SCHEDULE_CRON` | 空 | 同步根 / 只处理的子目录 / 定时 cron。**写了会盖住网页上的修改**，一般在网页上选 |

## 命令行

网页是默认动作；命令行每条都在，适合定时 / 无人值守 —— 容器内跑 `docker exec 115strm python -m app <命令>`：

`serve`（开网页，容器默认）· `sync`（**跑一轮**）· `preview`（只预览，不写）· `export`（只导一次目录树）·
`pending`（看挂起的删除）· `apply --yes`（确认删除）· `doctor --check`（环境自检 + 前缀连通性验证）
