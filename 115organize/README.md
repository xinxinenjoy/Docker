# 115organize

**115 网盘的慢速整理工具** —— 把乱堆的网盘按「番号系列 / 影视作品」归好位，顺手清掉夹带的广告推广件。

两条铁约束贯穿全部设计：

1. **慢**。每一个请求之间 3–5 秒随机间隔，每 200 个请求长休 60 秒，还能限定只在凌晨跑。
   目的只有一个：**不触发 115 的风控**。
2. **不覆盖、不误删**。任何移动都显式声明「重名就并存」；清理默认是**移到隔离目录**而不是删；
   判不准的一律只报告。出厂默认是**只演练**：一个请求都不发，只在日志里说它本来要做什么。

带一个**网页界面**（默认动作就是开它）：看方案、按条目勾选、小批量试跑、改参数都不用碰命令行。

---

## 一、它能做什么

分成**两部分**，对应两种用法：

### 第 1 部分：整理已有目录（离线算方案，再慢速执行）

你已经从 115 导出了目录树（`.txt`），所以**不需要扫盘**：

```bash
python -m app serve  # 开网页，在上面看方案 / 勾条目 / 执行（推荐）
# 或者纯命令行：
python -m app plan   # 纯离线，读目录树算方案，出报告 + plan.json（不联网）
python -m app run    # 按方案执行（默认只演练，底部开关关掉才真动手）
```

| 动作 | 做什么 |
|:---|:---|
| **番号 → 系列** | `DLDSS-532` 这类番号目录收进 `DLDSS/`；一个系列满 `SERIES_MIN`(默认3) 部才建目录 |
| **番号目录改名** | `ipzz-916ch` → `IPZZ-916`（去掉 `-ch` / `-U` / `[4K]@站点` 这类尾巴） |
| **电影命名** | 按已有规则规范成 `片名（年份）` |
| **剧集收拢** | 散落的集文件收进 `剧名（年份）/第N季/` |
| **清广告** | 分级判定：强特征才动，白名单（封面/字幕/nfo）永不碰，灰区只报告 |

### 第 2 部分：入站口自动整理（轮询「待整理」目录）

115 **没有 webhook**，所以「有新文件就处理」只能靠轮询。入站口模式：
在整理根（如 `云下载`）下划一个「待整理」目录，**只监控它** ——
把要整理的东西丢进去，工具轮询发现后按规则归位（番号 → 系列、影视 → 影视区、
垃圾 → 隔离），处理完就移走。请求量只跟「你丢了几个东西」有关，跟盘的大小无关。

```bash
python -m app once    # 入站口整理跑一轮（处理「待整理」目录里的东西）
python -m app watch   # 常驻，每 INBOX_POLL_INTERVAL 秒轮询一次，有货就处理
```

> ⚠️ 入站口只处理**一层**子项，不递归 —— 深层整理用网页的「选定文件夹」功能。
> 想无人值守自动整理，容器跑 `serve` 时**再开一个容器**跑 `watch`、共用 `/data`。

## 二、快速开始

### 方式 A：Docker（推荐）

```bash
docker run -d --name 115organize \
  -p 8766:8766 \
  -e ACCESS_TOKEN='自己定一个口令' \
  -v /path/to/data:/data \
  --restart unless-stopped \
  xinxinenjoy/115organize:latest
```

等价的 compose：

```yaml
services:
  115organize:
    image: xinxinenjoy/115organize:latest
    container_name: 115organize
    restart: unless-stopped
    ports:
      - "8766:8766"
    environment:
      - ACCESS_TOKEN=自己定一个口令      # 内网 / 本机可以留空
      - PORT=8766
    volumes:
      - ./data:/data
```

然后浏览器打开 `http://<你的主机>:8766` —— 界面就是操作台。

> 🔴 **业务参数（阈值 / 节流 / 清理动作 / 定时…共 27 项）不再走环境变量。**
> 它们存在 `data/config.json` 里、**由网页「设置」页管**；环境变量只留上面那几个「引导项」。
> 原因：环境变量优先级最高，写进 `.env` 会把参数**钉死** —— 网页上改了不生效（页面上会标成
> 「环境变量」并给提示）。所以 `.env` 里**只放引导项**，业务参数一概别写。

**第一次跑，按这个顺序**：

1. 把 115 网页版导出的目录树 `.txt` 放进 `data/tree/`（见下节）
2. 网页 →「整理」页 → 点 **生成计划**（离线算，**一个请求都不发**）
3. 看计划摘要，然后在**条目**列表里先圈一小批（比如点「勾前 50 条」）→ 点 **算一下耗时**
4. **保持「只演练」开着** → 点执行 → 看下面的日志，确认它要做的事就是你想做的
5. 关掉「只演练」→ 再执行，这时才真的动网盘

> ⭐ 比起当年那个 `DRY_RUN` 环境变量，底部这条「只演练」开关好用得多：**不用改配置、不用重启
> 容器**，而且小批量试跑和批量真跑能混着来 —— 先勾几十条试水，确认没问题再勾更多。
> 出厂默认仍然是「只演练」，第一次打开页面不会误伤。

**cookie 从哪来**（按优先级从高到低）：

| 顺序 | 来源 | 说明 |
|:--|:--|:--|
| ① | 环境变量 `P115_COOKIE` | 临时 / 调试用，优先级最高 |
| ② | **`/data/accounts.json`** | ⭐ **推荐**。115offline 扫码登录后写的就是它 ⇒ 两个容器**挂同一个数据卷**即可共用，cookie 只维护一份 |
| ③ | `/data/cookie.txt` | 兜底。⚠️ 它是**死凭据**，过期了不会自己更新，所以排在活凭据后面 |

最省事的做法是让两个容器共用数据卷：

```yaml
    volumes:
      - /path/to/115offline/data:/data     # 115organize 只往里加 tree/，它不认这个子目录名
```

> 两个容器的数据目录实在合并不了，也可以用 `ACCOUNTS_FILE=/shared/accounts.json` 单独指路，
> 再用 `ACCOUNT_ID` 指定用哪个账号（用**账号 id**，不是名字）。
> 指了 `ACCOUNT_ID` 却找不到对应账号时会**直接报错停下来**，不会随手挑一个 —— 那等于在别人的盘上动手。


### 方式 B：本机直接跑

```bash
pip install -r requirements.txt
export TREE_DIR="目录树所在文件夹"          # 或者把树放进 data/tree/
python -m app doctor                        # 环境自检：目录树 / cookie / 依赖 / cron

python -m app serve                         # 开网页 → 浏览器进 http://127.0.0.1:8766
# 不想开网页也行，命令行一条条来：
python -m app plan
python -m app run
```

### 目录树怎么导出

115 的网页版有「导出目录树」功能，导出的 `.txt` 就是本工具的输入。
放进 `TREE_DIR`，`plan` 会自己挑**最新**的那份；想指定就设 `TREE_FILE`。
读得懂 UTF-16LE（带 BOM）/ UTF-8 / GBK。

## 三、命令一览

| 命令 | 说明 |
|:---|:---|
| `python -m app serve` | **网页界面**（容器里的默认动作）。`--host` / `--port` 可覆盖，默认 `0.0.0.0:8766` |
| `python -m app plan` | **离线**算方案，出 `plan.md` / `plan.json` / `plan-ops.txt` |
| `python -m app run` | 执行方案。默认**只演练**（零请求）；支持断点续跑与请求上限 |
| `python -m app once` | 入站口整理跑一轮（处理 `待整理` 目录里的东西） |
| `python -m app watch` | 常驻，轮询 `待整理` 目录，有货就处理（容器跑 `serve` 时另开一个容器跑它） |
| `python -m app stats` | 只看目录树规模统计 |
| `python -m app doctor` | 环境自检：目录树 / cookie / 目录可写 / 依赖 / 入站口配置 |
| `python -m app clear-state` | 清断点（想从头重跑时用） |

`run` 的常用参数：`--max-requests 50`（试跑，发够 50 个请求就收工并保存断点）、
`--no-resume`（忽略断点从头跑）、`--plan <路径>`。

> **网页和命令行是同一套引擎，两条路都留着**：网页适合「看着挑几条、小批量试」，
> 命令行适合「无人值守 / 入站口自动整理」。命令行每条子命令都还在，`serve` 只是多出来的一个
> （也是容器启动时的默认动作）。⚠️ 网页跑的是**你勾选的那个子集**，所以它写自己的断点
> `web-state.json`，**绝不碰**命令行的 `run-state.json` —— 否则命令行接着跑整份计划时，
> 会拿子集的计数当起点，**静默跳过一大批动作**。

## 四、配置

分两类，**别混**（完整模板见 [`.env.example`](.env.example)）：

### ① 引导项 —— 只有这几个走环境变量

| 变量 | 默认 | 说明 |
|:---|:---|:---|
| `ACCESS_TOKEN` | 空 | 网页口令。留空 = 不校验（仅限内网 / 本机）；**映射到公网必须设**。与 115offline 同名同语义，设成一样就一个口令管两个服务 |
| `PORT` | `8766` | 网页监听端口（容器内）。改了记得同步改端口映射右侧 |
| `DATA_DIR` | `/data` | 数据目录（容器内路径，不用改） |
| `ACCOUNTS_FILE` | `DATA_DIR/accounts.json` | 账号文件在哪 —— 用于复用 115offline 的登录态 |
| `ACCOUNT_ID` | 空 | 用哪个账号（**账号 id**，不是名字）。留空 = 第一个能用的 |
| `P115_COOKIE` | 空 | 直接贴 cookie，优先级最高。临时 / 调试用 |

> **为什么只有这几个留 env**：`DATA_DIR` 是**自我引用**（`config.json` 就住在它里面，
> 不能反过来去 config.json 里问「你自己在哪」）；其余几个要么是「进程怎么起来」的，
> 要么是**凭据** —— 都不该由网页里那个配置文件来定。

### ② 业务参数 —— 全部在网页「设置」页

**共 27 项、分 8 组**：115 账号 / 整理范围 / 番号系列 / 影视 / 垃圾清理 / 节流防风控 / 自动化 / 安全阀。
改完点 **保存改动**，落在 `data/config.json`，**立即生效、不用重启容器**。

优先级：**显式环境变量 > `data/config.json` > 代码默认值**。
想在网页上改某项，**就别在 `.env` 里设它** —— 页面上会把这类参数标成「环境变量」并给提示，
一眼看出被谁钉住了。

几个容易踩的（写的是网页上的叫法）：

| 参数 | 默认 | 说明 |
|:---|:---|:---|
| **只演练不动手** | **开** | 出厂默认不动手。每次跑之前都建议先开着演练一遍 |
| **清理动作** | 移进隔离目录 | 可撤销的那一档。改成**删除**（进 115 回收站）之前先想清楚 —— 115 的「删除」和「还原」是互斥的 |
| 系列聚合阈值 | `3` | 一个系列满几部才建目录 |
| 单请求间隔下限 / 上限 | `3` / `5` 秒 | 之间**随机**取 |
| 长休前请求数 / 长休时长 | `200` / `60` 秒 | 长休时点「停止」最多 0.25 秒就响应（内部切成小段睡的） |
| 只在那个时间段 | 空 | 如 `02:00-06:00`；窗外就地等 |
| 入站目录名 | `待整理` | 自动整理只监控这一个目录。把要整理的东西丢进去，处理完移走 |
| 入站口轮询间隔 | `60` 秒 | 115 没有 webhook，只能轮询。每次轮询 = 列一次入站目录（1 个请求） |
| 扫描间隔下限 / 上限 | `0.5` / `1.5` 秒 | 只影响「选定文件夹」的**接口扫描**（列目录），不影响执行。量小、影响小，可比整理快 |

**三档节流**（间隔下限 / 上限 / 每多少请求长休 / 休多久）—— 在网页「节流防风控」组里调：

| 档 | 值 | 什么时候用 |
|:---|:---|:---|
| 频繁 | `1 / 2 / 500 / 30` | 盘小、想快点看完 |
| **常规（默认）** | `3 / 5 / 200 / 60` | 一般情况 |
| 保守 | `8 / 12 / 100 / 600` | 刚被风控过 / 盘很大 |

## 五、安全设计（为什么敢让它动我的盘）

| 措施 | 说明 |
|:---|:---|
| **默认只演练** | 出厂就是演练模式：**一个请求都不发**（连根目录 id 都不查），只在日志/报告里说它本来要做什么。网页底部那个开关关掉才真动手 |
| **绝不覆盖** | 每次移动都显式带 `keep_both`。115 对文件的默认策略是 `replace` —— **覆盖且不可恢复**，所以这个参数一次都不省 |
| **清理不删** | 默认 `quarantine`：移到 `_待清理/<原目录名>/`，**保留原名、按来源分桶**，可整目录撤销 |
| **冲突即停车** | 两个源归一到同一目标（本盘真实存在 5 组）⇒ 标 `auto=False`，**不执行**，只在报告里列出来等人裁决 |
| **不认识就不动手** | 动作类型白名单外的、计划里没有的，一律拒绝执行（宁可不动，不猜着动） |
| **判不准只报告** | 垃圾判定分三级，灰区 1,700+ 条只进报告 |
| **失败即冷却** | 连续失败 8 次（风控与网络抖动的症状一样）就停手冷却 15 分钟 |
| **断点续跑** | 中途挂了重跑不会重复动手（四个 pass 各自记断点） |

## 六、它不会做什么

- **不下载、不上传、不刮削元数据**。它只做移动/改名/清理。想要封面、简介、演员表，
  那是 [JavSP](https://github.com/Yuukiy/JavSP) / [MoviePilot](https://github.com/jxxghp/MoviePilot) 的活。
- **不递归扫全盘**。没有目录树就不能算全盘方案；入站口只碰「待整理」那一层，选定文件夹只碰你勾的那几个。
- **不认 115 的「分享 / 离线下载推送」**。想推磁力去用同仓库的
  [115offline](https://github.com/xinxinenjoy/Docker/tree/main/115offline)。
- **不并发**。115 明确写了 `fs_move` / `fs_delete` **请不要并发执行** —— 本工具全程串行。

## 七、规则是怎么来的

判别规则不是拍脑袋写的：

- **番号识别**照抄 [JavSP](https://github.com/Yuukiy/JavSP)（5,179★，`javsp/avid.py`，GPL-3.0）的规则**顺序**，
  噪声词表则来自你这份真实目录树的**逐条计数**（如 `第一會所新片@` 出现 218 次、后缀 `-C` 502 次）。
- **命名规则**（电影 `片名（年份）`）直接复用本仓库
  [`115offline/app/namer.py`](../115offline/app/namer.py)，两边**同步**（`tests/check_namer.py` 是同一份回归用例）。
- **垃圾判定**的词表拆成「出现即判」与「必须叠加跨目录重复」两级 ——
  实测第一版把 `…撸先生和玲的射4分钟.mp4` 这类**正片**误判成广告（2,194 条误报），
  收紧词表后降到 1,150，再叠加重复度门槛后约 1,000 上下（随盘上内容浮动）。

## 八、开发

```bash
python -m unittest discover -s tests        # 74 个用例，约 1 秒，不需要装任何第三方依赖
python tests/check_namer.py                 # 命名规则独立脚本（与 115offline 共用）
```

用例全部离线：节流器的时钟与 sleep 是**可注入**的（否则验「4 小时跑完」要真等 4 小时），
115 那层用**假 client** 顶掉（能断言每次都传了 `keep_both`、翻页没漏、请求没绕过节流）。

## 九、局限 / 已知取舍

- **番号系列阈值一刀切**：`SERIES_MIN=3` 意味着只出现 1–2 次的番号不会被聚合
  （实测 548 个系列里 262 个只出现 1 次，全聚合会制造大量碎片目录）。想要全聚合就设 1。
- **电影只认「有年份 + 有清晰度标签」的**。纯英文名一律不改名 ——
  曾经改过一个 `6.Underground.2019…`，把开头那个 `6` 弄丢了。
- ⭐ **目录树导出分不清「空目录」和「文件」**（导出格式**没有类型标记**，两者都表现为
  「名字 + 没有下一层缩进」）。实测：真机 `云下载` 下是 **7,544 个目录 / 154 个文件**，
  我们按缩进能算出 **7,494 / 203** —— 那多出来的约 50 个就是空目录。影响往下走有两处，
  都已做了闸门：
  - 移动：`move_dir` 只移目录、`move_file` 只移文件，类型不符**跳过**（不是硬移）；
  - 清理：受 `JUNK_ALLOW_DIR` 管 —— 默认允许动目录（判据是按**名字**做的，目录一样成立，
    且默认动作是**可撤销**的 `quarantine`）；设 0 则只清文件、目录跳过并报出条数。
- **`count` 缺失时靠翻页试探**，极端情况（接口不认 `offset`）会在 500 页处收手并告警。
- **不动 `115电影` 那块**：`ROOT_PATH` 一次只指一个根，想整理另一块就另跑一份配置。
