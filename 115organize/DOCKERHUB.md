# 115 网盘慢速整理

把乱堆的 115 网盘**按番号系列 / 影视作品归好位**，顺手清掉夹带的广告推广件 ——
全程**慢速**（请求间隔 3–5 秒随机 + 定期长休），**默认只演练、一个请求都不发**。

带一个网页界面：看方案、按条目勾选、小批量试跑、改参数，都不用碰命令行。

## 功能

- **番号按系列归位**：`DLDSS-532` → `DLDSS/DLDSS-532`，系列满 3 部才建目录
- **番号目录改名**：`ipzz-916ch` → `IPZZ-916`（去掉 `-ch` / `-U` / `[4K]@站点` 尾巴）
- **电影命名**：规范成 `片名（年份）`
- **剧集收拢**：散落的集文件收进 `剧名（年份）/第N季/`
- **清广告推广件**：分级判定 —— 强特征才动，正规封面/字幕永不碰，判不准的只报告
- **入站口自动整理**：只监控一个「待整理」目录，有东西就处理，处理完移走 —— 请求量跟盘大小无关，不扫全盘
- **选定文件夹整理**：网页上勾选要整理的文件夹（目录树离线 / 接口慢速扫描），只动勾中的范围

## 使用方法

**① 起容器**

```bash
docker run -d --name 115organize \
  -p 8766:8766 \
  -e ACCESS_TOKEN='自己定一个口令' \
  -v /path/to/data:/data \
  --restart unless-stopped \
  xinxinenjoy/115organize:latest
```

等价的 compose：

```yaml
services:
  115organize:
    image: xinxinenjoy/115organize:latest
    container_name: 115organize
    restart: unless-stopped
    ports:
      - "8766:8766"
    environment:
      - ACCESS_TOKEN=自己定一个口令      # 内网 / 本机可以留空
      - PORT=8766
    volumes:
      - ./data:/data
```

然后浏览器进 `http://<你的主机>:8766`。

**② 放进目录树** —— 115 网页版能导出整个目录树，把那份 `.txt` 丢进 `/data/tree/`。

**③ 在网页上走一遍**

1. 「整理」页 → **生成计划**（离线算，不发任何请求）
2. 看计划摘要 → 在**条目**列表里先圈一小批（比如点「勾前 50 条」）→ 点「算一下耗时」
3. **保持「只演练」开着** → 点执行 → 看日志，确认它要做的事就是你想做的
4. 关掉「只演练」→ 再执行，这时才真的动网盘

## 命令

网页是默认动作（`serve`）；命令行每条都还在，适合定时 / 无人值守。

| 命令 | 说明 |
|:---|:---|
| `python -m app serve` | 开网页界面（容器默认动作），默认 `0.0.0.0:8766` |
| `python -m app plan` | 离线算方案（不联网），出报告 |
| `python -m app run` | 按方案执行（默认只演练、零请求） |
| `python -m app once` | 入站口整理跑一轮（处理「待整理」目录） |
| `python -m app watch` | 常驻，轮询「待整理」目录，有货就处理 |
| `python -m app doctor` | 环境自检 |

## 安全

- **默认只演练**：一个请求都不发，只在日志/报告里说它本来要做什么 —— 网页底部那个开关关掉才真动手
- **绝不覆盖**：每次移动都显式带「重名就并存」（115 对文件的默认策略是覆盖，且不可恢复）
- **清理不删**：默认移到 `_待清理/`，**可整目录撤销**
- **判不准只报告**；目标冲突一律**不执行**，列出来等人裁决
- **慢**：单请求 3–5 秒随机间隔，每 200 个请求长休 60 秒，可限定只在凌晨跑

## 变量

**只有「引导项」走环境变量**；业务参数（阈值 / 节流 / 清理动作 / 定时…共 27 项）在网页
**设置**页里管，存在 `data/config.json`，改完立即生效、不用重启容器。

| 变量 | 默认 | 说明 |
|:---|:---|:---|
| `ACCESS_TOKEN` | 空 | 网页口令。留空 = 不校验（仅限内网 / 本机）；映射到公网必须设 |
| `PORT` | `8766` | 网页监听端口（容器内） |
| `DATA_DIR` | `/data` | 数据目录 |
| `ACCOUNTS_FILE` | `DATA_DIR/accounts.json` | 账号文件位置 |
| `ACCOUNT_ID` | 空 | 用哪个账号（id）；留空 = 第一个能用的 |
| `P115_COOKIE` | 空 | 直接贴 cookie，优先级最高。临时 / 调试用 |

**cookie 怎么来**：优先读 `/data/accounts.json`（同仓库的
[115offline](https://github.com/xinxinenjoy/Docker/tree/main/115offline) 扫码登录后写的就是它）
⇒ **两个容器挂同一个数据卷就能共用登录态，cookie 只维护一份**；其次才是 `/data/cookie.txt`
（死凭据，过期不会自己更新）。
