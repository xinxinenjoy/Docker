# 115 离线推送

自托管的 **115 网盘离线下载推送工具**。手机浏览器打开网页，粘贴磁力 / ed2k / HTTP 链接，一键推给 115 离线下载。

为「不想为此专门开电脑」而做：把它跑在常年开机的机器上（NAS / 小主机 / 云服务器都行），手机随时可用。

> ## ⚠️ 跑之前先看这里（NAS / 小主机用户）
>
> **两套变量必须配，否则起来也用不了：**
>
> | 变量 | 必填 | 说明 |
> |:---|:---|:---|
> | `ACCESS_TOKEN` | 建议必填 | 访问口令。**一旦映射到公网，不设它等于把账号交出去** |
> | `DATA_DIR` | 默认 `/data` | 数据目录（存 115 cookie），**必须挂到宿主机**，否则容器重建后账号全丢 |
>
> 端口**容器内固定 8765**，映射到宿主机哪个随意。cookie 的获取步骤见下面「使用方法」。

---

## 功能

### 推送
- **多账号** —— 可保存多套 115 cookie（主号 / 小号 / 家人的），界面下拉切换；**扫码登录**（7 个端，默认推荐「电视端」）或 cookie 登录都行
- **批量粘贴** —— 一次贴一大段，自动挑出链接；紧挨着粘（无换行 / 无空格 / 只用逗号顿号相隔 / 夹带从网页复制来的零宽字符）也能正确拆开
- **中文暗号还原** —— 直接粘**百家姓** / **核心价值观** / **与佛论禅（佛曰）** 三种暗号，自动还原成链接；**链接与暗号可以混着粘**，每行一条
- **自动去重** —— 同一个种子写了两遍只推一次（按 info_hash 判定）
- **32 位磁力自动转 40 位** —— 磁力链里的 `btih` 是 32 位 base32 编码时 115 常识别不了，工具会自动转成 40 位 hex
- **选保存目录（多级下探）** —— 面包屑逐级进入 115 的目录树，可设为本账号默认；也能直接手填目录 ID

### 任务与整理
- **任务记录** —— 按「已完成 / 下载中 / 全部」筛选，查看进度与落地目录
- **一键整理改名**（手动触发，先预览后执行）
  - 顶层目录 → `片名（年份）`，没有年份就 `片名`；多部/多季用 `片名（系列）`
  - 多季剧 → 下面再分 `第1季` / `第2季`
  - 分集文件 → `剧名.SxxExx.第 N 集.集标题.ext`；没有集标题就是 `剧名.SxxExx.ext`
  - 括号**全角（）/ 半角() 可切换**；候选名可手改；**原名叫什么就记着**，改回去即等于撤销
- **手动多选删除** —— 广告文件不做自动判定（判不准），**勾选后手动删**；删掉是**进 115 回收站**，不是彻底删除
- **回收站** —— 列出最近删除（倒序）+ **多选还原**
- **批量操作不并发** —— 改名 / 删除 / 还原都走「分块 + 块间延时 + 全局单飞」，因为 115 的接口文档明确写着删除**请不要并发执行**、删除与还原**互斥**

### 账号
- **用量与空间** —— 离线次数（剩余 / 已用 / 总配额）+ 网盘空间（已用 / 总容量 / 剩余）
- **访问口令** —— 可选，防止网址被别人拿到就能用你的账号

## 支持的平台

| 平台 | 覆盖设备 |
|:---|:---|
| `linux/amd64` | x86-64 的 PC / NAS / 云服务器 |

镜像名 `xinxinenjoy/115offline`。

> ⚠️ **只提供 `linux/amd64`（x86-64）** —— 现在绝大多数 NAS / 小主机 / 云服务器都是这个架构。
> 本项目**明确不支持 ARM**：`arm/v7`（32 位）下 `brotli` / `zstandard` / `cffi` 都没有预编译轮子
> （piwheels 也没有 cp312 的），必须现场编译 —— 实测**单是安装依赖就要 30 分钟**，占整个构建时长 88%，
> 且连 64 位的 `arm64` 也需要额外工具链，**性价比太低、放弃**。
> ARM 设备（树莓派等）请自行在设备上构建，或改用其他方案。

## 快速开始

### 方式一：`docker run`

```bash
docker run -d --name 115offline \
  -p 8765:8765 \
  -e ACCESS_TOKEN=换成一个够长的口令 \
  -v /path/to/data:/data \
  --restart unless-stopped \
  xinxinenjoy/115offline:latest
```

### 方式二：`docker compose`

```yaml
services:
  115offline:
    image: xinxinenjoy/115offline:latest
    container_name: 115offline
    restart: unless-stopped
    ports:
      - "8765:8765"
    environment:
      - ACCESS_TOKEN=换成一个够长的口令
      - DATA_DIR=/data
      - TZ=Asia/Shanghai
    volumes:
      - ./data:/data
```

```bash
docker compose up -d
```

然后打开 `http://部署机器的IP:8765`。

### 方式三：自己构建

```bash
git clone <本仓库>
cd Docker/115offline
docker build -t 115offline:latest .
```

## 环境变量

| 变量 | 默认 | 说明 |
|:---|:---|:---|
| `ACCESS_TOKEN` | 空 | 访问口令。设置后打开网页需先输入。**一旦映射到公网，务必设一个长的** |
| `DATA_DIR` | `/data` | 数据目录，里面是 `accounts.json`（存 115 cookie） |
| `TZ` | 容器系统 | 时区，如 `Asia/Shanghai` |

**端口** —— 容器内固定监听 `8765`，映射到宿主机哪个端口随意（上面示例也映射成 8765）。

**数据持久化** —— cookie 存在 `DATA_DIR/accounts.json`。务必把 `/data` 挂到宿主机，否则容器重建后账号全丢。

## 使用方法

### 第一步：拿 115 cookie

1. 电脑浏览器打开并登录 [115.com](https://115.com)
2. 按 `F12` 打开开发者工具 → 切到 **网络 / Network** 面板
3. 刷新页面，点任意一个发往 `115.com` 的请求
4. 在 **请求头 / Request Headers** 里找到 `Cookie:`，**整行值复制下来**
5. 里面的 `UID=` `CID=` `SEID=` 三个是必需的，别漏

粘进工具的「账号」页保存即可，工具会顺手校验一次并显示昵称。

### 第二步：推送

1. 在「推送」页粘磁力链接（**一次可以贴一大段，中间夹着别的文字也行**，工具会自己挑出链接）
2. 点「解析」看一眼挑出来的条目（32 位的老磁力会显示「已修正 40 位」）
3. 需要的话选保存目录
4. 点「推送到 115 离线下载」

然后去 115 的离线下载列表里就能看到任务了。

## 安全提醒

- 115 cookie **等同于账号登录态**，拿到它就能操作你的网盘。工具只把它存在你自己的 `DATA_DIR` 里，不上传任何第三方。
- **一旦把端口映射到公网**（端口转发 / 反向代理），**务必设置 `ACCESS_TOKEN`**，否则任何知道网址的人都能用你的 115 拉东西。
- 建议走 HTTPS（Nginx / Caddy / 反向代理 + 证书），否则口令在链路上是明文。

### 反向代理示例（Nginx）

```nginx
location /115/ {
    proxy_pass http://127.0.0.1:8765/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```

## 关于 cookie 有效期

工具**不保活 cookie** —— 只在调用 115 接口的那一刻才使用，没有后台心跳、没有定时续期。所以「会不会失效」完全取决于 115 服务端，与工具无关。

**让 cookie 活得久的关键是选对端**：同一个端**再次**扫码登录，会把该端旧 cookie 挤掉（所有在用这份 cookie 的地方一起掉线）。所以扫码时挑一个**平时不用的端**（电视端 / 支付宝小程序之类），并且**避免与已有工具撞端**。

失效后：在账号页点「校验」会刷新状态；换新 cookie 在账号页点「换 cookie」直接贴进去即可（**不必删号重加**）。

## 技术说明

- 115 的接口有**签名**（`sign` + `time`）且会变，本项目把这块交给 [`p115client`](https://github.com/ChenyangGao/p115client) 处理，不自己复刻；接口变更时升级该库即可跟上。
- 后端 FastAPI + uvicorn，前端单文件 HTML（无构建步骤）。
  > ⚠️ 依赖里**故意不用 `uvicorn[standard]`** —— 那个 extra 会拉 `uvloop` + `httptools` 两个 C 扩展。去掉后退化为纯 Python 的 asyncio + h11，功能一致、性能略降，换来依赖里零编译包、镜像更小。

## 已知限制

- 走的是 115 **网页版接口**（非官方开放平台），存在风控可能。**批量推送别一次几百条**，建议分批。
- ⛔ **不提供「彻底删除 / 清空回收站」** —— 那是不可恢复的操作。原因不是保守：2026-10-05 实测调用 115 的
  `/rb/secret_del`（即使**明确只指定了单个 id**）会把**整个回收站清空**，而且是**异步**生效、当场看不出来。
  所以本工具只管「删除进回收站 + 还原」，永久删除请去 115 官方界面自己点。
- 整理改名是**纯本地字符串处理，不联网查库**（不接 TMDB）。所以：
  - 它只会**删噪声 + 套格式**，不做片名纠错、不保证认得出每部片子的正确年份
  - 认不出年份时，可以选择用**离线任务的添加年份**兜底
  - 所有结果都必须在预览页人工确认后才写回 —— 它给的是**候选**，不是终稿
- 广告文件**不做自动判定**（判准率不够），只给「疑似广告」标记做筛选，删不删由人勾选。
- 115 离线列表里已存在的任务无法重复添加，这是 115 侧的限制。
